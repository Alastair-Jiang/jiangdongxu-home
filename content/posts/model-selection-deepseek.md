给 DAFT 选主力模型时，候选只有两个：DeepSeek V4 Flash 和 Kimi K3。K3 刚发布时是当时最大的开源模型（2.8T 参数、896 个专家），DAFT 的架构灵感也来自它。但最后主力模型选了 V4 Flash，K3 只留作架构审查。这篇文章记下这个决策和它背后的账。

## 一张对比表

（2026 年 8 月，SuperCLUE + Artificial Analysis 数据）

| 维度 | V4 Flash | Kimi K3 |
|---|---|---|
| 价格（每百万 token） | $0.15 输入 / $0.29 输出 | $3 输入 / $15 输出 |
| 单任务耗时 | ~29 分钟 | ~73 分钟 |
| 数学推理（SuperCLUE） | #1（78.95） | 未进前三 |
| Agent 编程 | 46.46（#3） | 60.61（#1） |
| Intelligence Index | 50 | 57 |

## 为什么是 V4 Flash

**1. 数学推理排第一，恰好是量化最需要的。**

量化金融项目的核心不是写代码，是推导和验证公式——safe gate 的数学、换手率的成本模型、IC 的显著性。V4 Flash 在这个维度上是 #1，超过了 K3。

**2. 便宜 30 倍，学生预算下几乎免费。**

K3 的输出要 $15/M，V4 Flash 是 $0.29/M。同样的任务，一个要几十块，一个几毛钱。这不是「选贵的更稳」的问题，是量级差异。

**3. 零迁移成本。**

整个链路——Claude Code、OpenClaw 协作、Telegram bridge——已经在 Anthropic Messages 协议上跑通了。V4 Flash 原生兼容这套协议，切 K3 要新建 OpenAI SDK 适配，得不偿失。

**4. K3 强制 thinking=max，在 agent 循环里是纯负担。**

K3 的思考模式在单次问答里很好，但在 Claude Code 这种多轮 agent 循环里，每步都深度思考会拖慢节奏、烧 token。

## K3 留在什么位置

不是 K3 不好——是专长不同。V4 Flash 高效实现代码，但在「逐行验证数学公式」「跨文件因果推理」「架构级质疑」这种深度审查上，力不从心。

所以现在是双层路由：**V4 Flash 做程序员（日常编码、测试、git），K3 做工程师（架构审查、数学验证、root cause 推理）**。触发条件很明确：涉及数学/梯度、跨文件因果链、新增架构组件、训练结果异常 → 路由给 K3，其余一律 V4 Flash。

## 结论

选型不是「哪个模型更强」，是「哪个模型在这个项目里，用这个预算，做这件事更划算」。对 DAFT 来说，答案是 V4 Flash。数学推理 #1 + 便宜 30 倍 + 零迁移成本，这三条加起来，K3 的 Intelligence Index 高 7 分也换不回来。
